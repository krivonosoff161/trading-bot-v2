# TASK для Codex — инфо-эдж + непрерывный AI-сканер (31.05.2026, эксперимент сравнения с Claude)

## БОЛЬШАЯ ЦЕЛЬ (финальная структура, видение трейдера)
Непрерывный **AI-сканер на ОДНОЙ бирже (OKX)**: стримит (НЕ опросами) новостной поток (крипта/альты/коины) + данные биржи (цена/объём/стакан/funding/OI/новые листинги), и **«слабый ИИ» (LLM) ПОСТОЯННО принимает решения о торговле** (монета + сторона + стоп/инвалидация). По сути — дискреционный трейдер-аналитик, только автоматический, 24/7, по всему рынку. PAPER-first.

Архитектура (как видим):
```
[СТРИМ, постоянно:  OKX WS цены/трейды/стакан/funding/OI + детектор новых листингов
                    + новостной поток (скаут-источники, near-real-time)]
        ↓
[ДЕШЁВЫЙ пре-фильтр: флажки кандидатов (всплеск объёма, новый листинг, новость по монете,
                    funding-экстрим) — чтобы НЕ дёргать LLM на каждый тик (цена/латентность)]
        ↓
[ИИ-РЕШЕНИЕ (слабый LLM, у нас Qwen):  {монета, рынок, новость, контекст} →
                    торговать/нет · сторона · стоп · уверенность]
        ↓
[PAPER-исполнение + ЛОГ:  реалистичный филл (тейкер+слиппедж, особенно новые/неликвид)
                    → каждое решение+обоснование+ИСХОД в signals/outcomes/training.jsonl]
        ↓
[ФОРВАРД-ТАБЛО:  WR / net-после-костов / vs baseline — честный счёт]
```
Новые листинги («самый сок» — бешеный рост/падение, истории нет) встроены в стрим как приоритет.

## ЖЁСТКАЯ ПРАВДА / честный гейт (не обойти — иначе самый дорогой мираж)
**«ИИ принимает решения» ≠ «ИИ зарабатывает».** LLM на непредсказывающих входах = уверенный ШУМ после костов. Новости по крипте часто УЖЕ в цене (наша охота: lead-lag = 0, премув ≈ 0σ — публичные новости в хвосте информации). Значит:
1. НАЙТИ, какие входы реально предсказывают ход (чтобы кормить ИИ не мусором).
2. PAPER-first: логировать КАЖДОЕ решение + исход, мерить форвардом против baseline.
3. Реальные деньги — ТОЛЬКО если paper докажет net-плюс после костов.

**Ветка B — feasibility непрерывной архитектуры на OKX:**

Decision-слой делать **плаг-ин** (свап облако↔локаль = одна настройка); когда соберём — A/B обе модели на одном paper-логе, оставить «достаточно хорошую» / дешевле.
