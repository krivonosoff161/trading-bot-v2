## Constrained Strategy Optimizer (Optuna + Ollama)
- Дата: 2026-04-02

**Идея:** автоподбор параметров стратегии через Optuna (Байесовская оптимизация) вместо ручного перебора. Ollama (локальная 3B модель) как explain-layer для интерпретации top-10 результатов человеческим языком.

**Цепочка:** Optuna берёт комбинацию параметров → запускает backtest_simulate.py → получает метрики → запоминает что работает → после 200-500 итераций выдаёт лучшие параметры.

**Главный риск — переобучение:**
- Текущие данные: 56 дней, 4 периода, одни и те же пары, одна эпоха рынка
- P2 сильно тащит OVERALL, ручных итераций поверх этих данных уже много
- "Идеальные" параметры для этого окна = ухудшение на следующем месяце

**Поэтому строить только как constrained optimizer:**
1. Цель не "макс PF", а составная: макс PF при ограничениях signals/day ≥ X, DD ≤ Y, max SL серия ≤ Z, ни один период не должен быть катастрофическим
2. Оценивать стабильность по периодам, не только OVERALL
3. Узкое пространство поиска: только `drift_vol_min`, `fast_adx`, `ranging_adx_max`, maybe `strong_4h_veto di threshold` — не параметры выхода пока не закрыта проблема TIME_EXIT
4. Backtest должен давать machine-readable output (сейчас только текст)

**Что нужно сделать раньше:**
1. Накопить signal_log + labels (100+ записей)
2. Понять есть ли реальный edge в microstructure (obi5, delta, spread)
3. Зафиксировать список разрешённых к оптимизации параметров
4. Только потом — constrained Optuna

**Ollama в этой схеме:** не в поиске, только summary после. GTX 1050 тянет qwen2.5-coder:3b (2GB VRAM) — хватит для explain-layer.

**Статус:** после накопления live labels и фиксации baseline — приоритетная идея.

## Multi-agent graph analysis (MiroFish архитектура)
- Дата: 2026-03-21

## FADE / Mean Reversion — контртрендовый вход на экстремуме

## 🔴 HIGH: DRIFT regime — слепая зона engine (30.03.2026)

**Проблема:** бот видит только два языка рынка — impulse/expansion (TRENDING) и fade от края диапазона (RANGING). Плавный intraday directional grind без объёма и без высокого ADX он не торгует. Проверено на данных 2026-03-28..30: 30 марта BTC дрейфовал +3.2% с полуночи до 13:00 UTC, ETH +2.81%, SOL +2.08% — бот молчал всё утро, дал только SELL на вершине дня.

**Гипотеза:** нужен третий режим внутри текущего engine — не отдельный модуль, а новый `regime branch`. Назвать `DRIFT`.

**Критерии детекции DRIFT** (Codex + Claude, 30.03.2026):
- EMA20_1H slope направлен в одну сторону минимум 3 закрытых бара подряд
- Цена держится по одну сторону VWAP (persistence, не разовый факт)
- EMA20_1H и EMA50_1H не конфликтуют (не обязаны широко расходиться)
- ADX_1H в окне 10–18 (не мёртвый, но не тренд)
- На 5m нет пилы через EMA20 (нет частых flip-flop)

**Почему не просто slope EMA:** слишком шумно само по себе. Только в сочетании с VWAP persistence и low-noise 5m структурой.

**Next step:** design + backtest на данных 2026-03-28..30 (данные уже есть, weekend идеальный тест-кейс).

**Важно:** это не новая стратегия — это новый `market language` внутри текущего engine. Реализация: добавить ветку `elif _regime == "DRIFT"` рядом с TRENDING/RANGING/CHOPPY.

Возвращает (bias, confidence, strength). Чистый Python, детерминированный. Файл: `src/strategies/scalping/futures/patterns/pattern_engine.py`. Взять как есть когда понадобятся дополнительные фильтры входа.

- [2026-04-02] **Margin Calculator** — точные формулы расчёта цены ликвидации OKX. Long: `LiqPrice = Entry × (1 - 1/Leverage + MaintenanceMargin)`. Short: обратная формула. Автозакрытие до ликвидации с буфером маржи. Файл: `src/strategies/scalping/futures/calculations/margin_calculator.py`. Взять когда будем переходить на реальный счёт.

- [2026-04-02] **Reentry Guard (Anti-Churn)** — кулдаун перед повторным входом: 60s та же сторона, 180s после убытка, 5s противоположная сторона. Предотвращает цепочки open→close→open. Конфиг в YAML. Рассмотреть вместе с Daily Stop Limit (уже в бэклоге, 2026-03-28).

- [2026-04-02] **Adaptive Leverage по балансу** — автоматическое изменение плеча в зависимости от текущего баланса и волатильности. Профили: micro ($0-500) → large ($3000+), плечо 5x-20x. Рассмотреть при переходе на реальный счёт с инвесторами.

- [2026-04-02] **Non-Critical Confirmation Window** — для некритичных выходов требовать 2-3 подтверждения за 3 секунды, не срабатывать на одном спайке цены. Критичные выходы (emergency) обходят проверку. Архитектурная идея для exit логики.

### Из репо `new-boot` (Soveryn — коммерческая платформа)

- [2026-04-02] **Adaptive Capital Distributor** — распределение капитала между парами с учётом корреляции (не держать все 5 пар одновременно если корреляция >0.9), волатильности и размера счёта. 3 режима: CONSERVATIVE/AGGRESSIVE/AUTOMATIC. Ребалансировка при $200+ изменениях. Рассмотреть при мультипользовательском копи-трейдинге (S2).

- [2026-04-02] **ML Signal Engine (ensemble)** — RandomForest + GradientBoosting + SVR на исторических результатах сигналов. 14+ признаков из свечных данных. Graceful degradation без scikit-learn. Рассмотреть после накопления 500+ labeled сигналов в signal_labels.jsonl — тогда будет достаточно данных для обучения.

- [2026-04-02] **Subscription System (5 уровней)** — Free → Basic → Professional → Premium → Enterprise ($999/мес). История платежей, лимиты по ботам/капиталу/API-вызовам. Soveryn реализовал полностью, можно взять за основу. Рассмотреть в S2 при монетизации Concierge Analyzer.

### Урок из обоих проектов

Оба провалились по одной причине: **слишком широкий scope до первого работающего продукта**. Репо `1` — 155 модулей, репо Soveryn — 33 торговых модуля + ML + веб + подписки. Ни один не дошёл до реальной торговли. Текущий подход (минимум → демо → статистика → расширение) правильный.
