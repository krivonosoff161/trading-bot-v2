Вместе с WebSocket идут: CVD (Cumulative Volume Delta — дивергенции покупателей/продавцов для раннего выхода), OBI (Order Book Imbalance L5 — дисбаланс стакана для подтверждения входа, порог |OBI| > 0.4), Tape Speed (скорость агрессивных ордеров в секунду — фильтр боковика, порог > 5 сделок/сек), VWAP multi-TF (дневной VWAP как динамическая поддержка/сопротивление, откат к VWAP = точка входа). - [2026-03-07] [2026-03-07] Multi-Timeframe (MTF) анализ — ADX на старшем ТФ (15m или 1h) для определения режима рынка (стабильный, не реагирует на спайки), RSI + Range на младшем ТФ (1m или 5m) для точного входа. Сейчас ADX(5m) инерционный — один спайк держит его высоким 60-90 минут. MTF решает это: режим рынка видит "большую картину", вход ищет точку на мелком ТФ. Реализация: get_candles() уже есть, нужно загружать два ТФ в _tick() и передавать оба в get_signal(). Добавить в Фазе 1.3 после получения первой статистики на текущей версии.
- [2026-03-07] [2026-03-07] Cursor Automations (автономный агент по расписанию) — после Фазы 1.3 когда есть логи и статистика. Идея: агент запускается автоматически после каждой сессии бота, читает logs/, считает WR/PnL/avg hold time и пишет дайджест. Возможные сценарии: 1) ежедневный анализ логов → summary в Slack/Telegram, 2) поиск аномалий (ghost positions, SL ниже порога, перетрейдинг), 3) авто-обновление PLAN.md с реальной статистикой. Требует: рабочий бот с логами + настройка Cursor Automations + MCP для доступа к репо.

- [2026-03-08] [2026-03-08] Бэктестер на исторических свечах — загрузить 1m+5m свечи через OKX API, прогнать через src/strategy/signal.py в walk-forward режиме, симулировать TP/SL по high/low следующих свечей, отчёт: WR/PnL/drawdown. Позволяет тестировать стратегию без прогона живого бота. Добавить в Фазе 1.3 после накопления первой статистики через signals.jsonl.
- [2026-03-08] [2026-03-08] Range-стратегия (торговля по границам боковика) — ❓ под вопросом. Открытые вопросы: 1) Как определять что рынок в диапазоне? (ADX < 22 — текущий признак, но этого мало). 2) Как вычислять границы диапазона? (min/max за N свечей, Bollinger Bands, ручные уровни?). 3) Как рассчитывать TP/SL? (TP = середина диапазона, SL = за границу — логика другая чем в тренде). 4) Как совмещать с трендовой стратегией в одном боте? (отдельный модуль? переключатель режима?). 5) Риск: на выходе из диапазона в тренд — стратегия даст серию SL. Изучить после накопления статистики по текущей стратегии.

- [2026-03-08] [2026-03-08] Order Flow стратегия (WebSocket) — ручная сделка XRP 08.03.2026: вход 1.2980, выход 1.3509, +1196 USDT за 3 минуты на демо (макс плечо, весь баланс). Паттерн: double bottom ~1.28, второй тест слабее (declining aggression sellers), крупный покупатель виден в стакане, вход на sweepе стопов, breakout momentum вверх. Почему не сейчас: требует WebSocket (текущий бот REST polling 10s), CVD по тикам, real-time стакан L2. REST-бот физически не может поймать 3-минутное окно. Рассмотреть как отдельный проект после того как текущая стратегия докажет результат в цифрах. Потенциал: R:R 1:3-5, 2-5 сделок в день.

- [2026-03-09] [2026-03-09] Live Market Paper Mode — бот подключён к реальному API (без демо-флага), генерирует сигналы, но вместо ордеров ведёт виртуальные позиции. TP/SL проверяется по реальным свечам каждый тик. Плюс: реальные данные, нет демо-артефактов, чистая статистика сигналов. Минус: не тестирует исполнение, проскальзывание, частичные ордера. Цель: доказать что бот читает рынок до реального execution. Рассмотреть в Фазе 1.3 если демо-данные покажут нестабильность, или как замену демо после накопления 20-30 сделок на текущей стратегии.
- [2026-03-09] [2026-03-09] Pattern Registry / библиотека паттернов — не одна "умная стратегия", а небольшой реестр формализованных паттернов (например: Trend Pullback Breakout, Double Test Breakout, позже Range Rejection), где у каждого паттерна есть свои условия входа/выхода, разрешённые символы, статус (`test/active/disabled`) и отдельная статистика по `symbol + regime + pattern_id`. Идея: бот не придумывает паттерны сам, а хранит 2-3 явных паттерна и со временем умеет ослаблять или отключать слабые по статистике. Почему не сейчас: высокий риск переусложнения и переоптимизации до того, как хотя бы один паттерн доказал результат. Рассмотреть после Фазы 1.3, когда появится устойчивая статистика и станет ясно, что один паттерн уже работает.
