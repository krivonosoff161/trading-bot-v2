# PLAN - Trading Bot V2

## Текущий этап: ЭТАП S1 - Concierge Analyzer MVP

**Что строим сейчас:** не автоторгового бота, а показываемый анализатор графиков с оператором в контуре.

**Почему:**
- `Strategy E` закрыта и заархивирована в [docs/strategy_e_postmortem.md](c:/Users/krivo/trading-bot-v2/docs/strategy_e_postmortem.md)
- спрос проявился не на бот, а на понятный разбор графика
- analyzer-first даёт шанс быстрее показать ценность и получить первые деньги

**Критерий перехода к следующему этапу:**
- анализатор стабильно работает end-to-end
- output можно показывать без стыда
- есть 5-10 демонстрационных кейсов
- есть первые реальные пользователи или готовность платить

## Этап S2 - Productized Service

### Фаза S2.1 - Прокладка между системой и LLM
- [ ] Отделить data layer от текста/упаковки
- [ ] Ввести единый `analysis payload`:
  - рынок
  - сценарий
  - уровни
  - ограничения
- [ ] Подготовить LLM-agnostic слой для генерации ответа

**Результат:** система считает факты сама, а LLM только объясняет и упаковывает.

---

### Фаза S2.2 - Консьерж-сервис
- [ ] Единый входящий канал для запросов
- [ ] Единый шаблон ответа клиенту
- [ ] История запросов и результатов
- [ ] Базовый учёт стоимости запроса

**Результат:** сервис можно оказывать системно, а не вручную хаотично.

**Приоритет канала:** сначала Telegram-first intake и delivery. Web/interface рассматривается только после того, как Telegram-сценарий доказал спрос и удобство.

- [ ] Простая загрузка скрина

**Результат:** приложение масштабируется только после подтверждённого спроса.

---

## Что сознательно НЕ строим сейчас

- Новый live-бот
- Новую trading strategy в `main.py`
- WebSocket / order flow / smart money
- OCR как обязательную часть MVP
- SaaS-платформу с auth и кабинетом
- Автообучение / ML / self-learning
- Большой research framework на десятки модулей

---

## Правила этапов

- Не возвращаться к `Strategy E` и её вариациям без явного нового research
- Не смешивать bot-first и analyzer-first задачи в одном цикле
- Не строить следующий слой, пока предыдущий не показал пользы
- Сначала полезный output, потом автоматизация
- Сначала спрос, потом масштабирование
