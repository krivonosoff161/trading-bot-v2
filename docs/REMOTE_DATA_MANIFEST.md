# Remote Data Manifest

Updated: 2026-06-10

Purpose: tell remote agents which important project data exists locally but is
ignored by Git. Missing ignored files should not be treated as missing from the
real workspace.

## How To Use

1. Read this file before drawing conclusions from missing runtime data.
2. Check `.gitignore` and local handoff notes.
3. Request small sanitized summaries instead of raw private files.
4. Never request secrets, `.env`, API keys, Telegram tokens, full private logs, or
   user subscription data.
5. If docs and code disagree, verify against code first, then flag stale docs.

## Current Local Scanner Data

These are important for current scanner work and are usually ignored:

| Path / pattern | Local purpose | Safe request |
|---|---|---|
| `SESSION.md` | Local running handoff and current session memory. | Ask for a sanitized section or summary. |
| `TASK.md` | Tracked handoff. Usually visible, but may lag local session details. | Read directly, then ask if local context changed. |
| `.env`, `*.env` | API keys and runtime secrets. | Never request raw values. Ask whether dummy/demo mode is enough. |
| `data/scout/news_buffer.sqlite` | Durable scanner intake buffer: raw items, machine docs, normalized events, source health. | Ask for `news_buffer stats`, selected doc IDs, or aggregate counts. |
| `logs/scout/ingest_log.jsonl` | All incoming scanner items. | Ask for counts by source and time window. |
| `logs/scout/scanner_journal.jsonl` | Main scanner decision journal. | Ask for aggregate counts or selected sanitized rows. |
| `logs/scout/drops.jsonl` | Dropped/skipped scanner items and reasons. | Ask for drop reason counts by source/layer. |
| `logs/scout/routing_audit.jsonl` | Asset/layer/routing audit trail. | Ask for aggregate routing diagnostics. |
| `logs/scout/scanner_reasoning.jsonl` | Layer-agent/chief reasoning blocks. | Ask for selected sanitized examples. |
| `logs/scout/scanner_events.jsonl` | Structured event blocks linked by card id. | Ask for selected sanitized examples. |
| `logs/scout/scanner_outcomes.jsonl` | Forward outcomes generated by resolver. | Ask for summary by verdict/source/layer. |
| `logs/scout/scanner_training.jsonl` | Training-style joined decision/outcome records. | Ask for aggregate metrics only. |
| `logs/scout/scanner_memory.jsonl` | Compact memory records from scanner outcomes. | Ask for summary only. |
| `logs/scout/charts/*.png` | Generated scanner chart images. | Ask for a specific image if needed. |
| `logs_archive/` | Archived runtime/research history. | Ask for specific sanitized excerpts. |

```text
Please provide a sanitized summary/export. Do not share secrets or raw private logs.
```

## Safety Rules

- Never request OKX API keys, Telegram tokens, `.env`, or raw secrets.
- Never suggest live trading scripts as a workaround for missing data.
- Treat ignored files as local-only, not nonexistent.
- For research tasks, ask local Codex/user to run scripts against local data and
  return summarized metrics.
