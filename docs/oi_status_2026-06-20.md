# Honest OI coverage status + bounded keyless enrichment (Phase C)

**Goal.** Give open-interest a *measured, honest* status instead of an indefinite `NEEDS_OI_DATA`:
fetch keyless-public OKX OI, measure real coverage, and label it — with **no fake-pass** (thin
coverage is never merged as if full) and **no eternal pending** (structurally-absent OI is marked
terminal). OI is a DATA state and **never** grants `PAPER_FORWARD_READY` — it only gates whether an
OI family's sweep may run. Module: [oi_status.py](../src/research_lab/oi_status.py).

## Status vocabulary (closed, disjoint from any trade verdict)

| status | meaning | effect |
|---|---|---|
| `oi_available` | OI fetched AND merged coverage ≥ 0.5 | the only state that lets an OI family run; the `oi` field is written ONLY here |
| `oi_partial` | OI points exist but cover < 0.5 of the window | informational; **not** merged — the OI family stays honestly blocked |
| `oi_unmeasured` | no OI points for this instrument/window (retention < window or no series) | terminal — recorded so the farm stops re-polling forever |
| `oi_fetch_failed` | transient provider/network error | retried under a cap, then → `oi_unmeasured` |

**No eternal pending.** [farm_coordinator.py](../src/research_lab/farm_coordinator.py) `_drain_enrich_oi`
now, after `OI_MAX_ATTEMPTS` structural failures, marks the enrich task and the matching blocked OI
sweep `skipped: oi_unmeasured` instead of deferring indefinitely (tested).

## Live finding (keyless, bounded 12 symbols/tf, no account)

| timeframe | measured | oi_available | median coverage |
|---|---|---|---|
| 1h | 12 | 12 | 100% |
| 4h | 12 | 12 | 100% |
| 15m | 12 | 12 | 100% |

**OI is obtainable, including on 15m, at current window lengths.** The keyless rubik
`open-interest-history` endpoint, forward-filled onto the candle timeline, fully covers the current
~3-week 1h/4h/15m windows — the earlier "15m OI is unmeasurable due to retention" assumption did NOT
hold here. This **opens the data axis** the gate verdict named as the honest way forward
(change the *constraint*, not the pipeline).

**Caveat (honest):** forward-fill coverage ≠ OI *point density*. 100% coverage means every candle
carries an OI value at-or-before its timestamp; if raw OI points are sparser than the candles, fast
ΔOI is under-resolved. The coverage gate (≥0.5) passes, so OI families *can* run, but OI-feature
resolution should be checked when those families are actually swept.
