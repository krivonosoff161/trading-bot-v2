# Geometry / Entry-Quality аудит — находки (24.05.2026)

## Метод
Для каждой закрытой сделки реконструируем **post-entry** путь цены из тиков и меряем:
`post_mfe` (макс ход в нашу сторону ПОСЛЕ входа), `post_mae` (макс против), `net`.

**Важно:** записанный движком MFE был **завышен** — он считает по свечным high/low и
захватывает ход импульсной свечи ДО входа. Чистая метрика — наш post-entry тик-путь
(валидировано: окно входа выровнено gap +0s, опора = entry_price).

## Вывод (меняет приоритеты)
«WR ок, денег нет» — **не одна болезнь:**
- **impulse** — вход (заходили на выдохе спайка, lag ~2%). Мёртв, закрыт верно.
- **main_ws** — входы ХОРОШИЕ (MFE +1.34 > |MAE| 1.07, WR 56%, только 17% вход-в-топ). Чёткая
  диагональ «MFE→net». Хвосты net −22/−24/−27% **= АРТЕФАКТ ДАННЫХ (подтверждено свечными кейсами):**
  суб-центовые монеты (HMSTR @0.000158) ловят баг **B1 `round(x,4)`** → SL/TP/exit_price = мусор (0.0002),
  net бутафорский. Реальный ход HMSTR был ±0.57%. **→ main_ws чище, чем −0.77%; «катастрофы» = плохие данные,
  не риск.** Истинный net считать из тейпа, исключив дешёвые монеты (или после фикса B1).

## Re-sim модель выхода — РЕЗУЛЬТАТ (`geometry_resim.py`, `20_resim_variants.png`)
Чистый юниверс (без B1-дешёвых), net из тейпа по 1m-свечам, fee 0.1% (константа). 3 варианта на одних путях:

| канал | V1 «как сейчас» | V2 «потолок» (oracle) | V3 «ATR-стоп + трейл после +1R» |
|---|---|---|---|
| main_ws (n=71) | −0.15%/сд, WR 62%, **PF 0.79** | +1.97%/сд, PF 56 | **+0.10%/сд, WR 56%, PF 1.44** |
| bb_fade (n=13) | −0.33%/сд, WR 46%, **PF 0.78** | +2.79%/сд, PF 38 | **+0.30%/сд, WR 69%, PF 1.98** |

**Вывод доказан числом:** одна правка ГЕОМЕТРИИ ВЫХОДА (ATR-стоп + трейл вместо текущего стопа/мелкого TP)
**переворачивает оба живых канала из минуса в плюс** (PF 0.79→1.44 и 0.78→1.98). Движение есть (oracle
+1.97%/+2.79% на сделку = столько оставляем на столе), мы его теряли на выходе — теперь забираем часть.

⚠️ **Дисциплина (не зазнаваться):** n скромный (71/13), одно окно 12 дней, один режим; V3 — ПЕРВЫЙ
парам (K_STOP 1.5 / TRAIL_K 1.0), захватывает лишь ~5% потолка → есть куда тюнить, но и риск оверфита на
малом n. Oracle = нереализуемый верх. Fee 0.1% прокси.

## Свип V3 — РЕЗУЛЬТАТ (`geometry_sweep.py`, `21_sweep_heatmap.png`)
Сетка стоп×трейл (±половина@1R), train/holdout по времени.
- **main_ws (train 49 / holdout 22): ВЕСЬ surface зелёный (+0.06…+0.25 train) — это ПЛАТО, не шип = робастно.**
  Лучшая зона по holdout: стоп **2.0 ATR + трейл 0.5-1.0** → **holdout +0.36…+0.43%/сд, PF ~6, WR 77%, worst −0.4%.**
  Holdout НЕ ХУЖЕ train → не оверфит. ATR-стоп режет хвосты (worst всего −0.4%).
- **bb_fade (n=13, train 9 / holdout 4 — ТОЛЬКО направленческое):** хочет тесный стоп ~1.0 ATR → holdout +0.6%, но n крошечный, не вывод.
- **Трейл-только > «половина@1R»** (ранний партиал режет раннеров — то самое «TP забрал начало», bb11).
- Разный оптимум: main стоп ~2.0 (тренд-следование), bb ~1.0 (фейд фейлит быстро).

## Следующий шаг
Эдж на main **робастный** (плато + holdout держит). НО: одно окно 12 дней, bb n=13. **В прод НЕ несём.**
1) Копить форвард-данные → перепроверить плато на НОВЫХ сделках (signal-rate низкий — ускорить накопление).
2) Когда подтвердится на форварде — предложить как **paper-конфиг** (ATR-стоп ~2.0 + трейл ~1.0 на main; ~1.0 на bb),
   доказать на форвард-paper до любого реала. **Прод/живые движки не трогаем без отдельного GO.**

## 🔴 Аудит целостности сигналов (`signal_audit.py`) — 24.05: ОФИЦИАЛЬНЫЙ WR ЗАВЫШЕН
main_ws: **45%** сигналов с флагами; bb_fade **81%**.
- **ФАНТОМНЫЕ ФИЛЛЫ (главное):** 20% сделок main (14/70) **НЕ дошли до уровня `entry`, но получили исход —
  13 из 14 ВЫИГРЫШИ** (TP1×9, TP2×4), ноль убытков. `entry` = откатный УРОВЕНЬ (ниже цены для buy); лейблер
  НЕ проверяет факт филла → лонги, что не откатились но дошли до TP, считаются победами. **WR: записано 75% →
  fill-verified 62-63%.** Официальная цифра (журнал/снапшот) раздута на ~12 пп.
- **B1** (21): суб-центовые коины, round(x,4) ломает уровни. **PHANTOM** (3): SL/TP вне диапазона цены (HMSTR).
- **NOSTOP** (4): цена пересекла SL, но исход не SL → стоп не форсится в метке (ср. main04 держали −10%).
- **ENTRY** (24 main / 10 bb): `entry` = уровень, не цена сигнала → проверка филла обязательна.

**Следствие:** sweep V3 гонялся на НЕ-fill-верифицированных сделках → его +0.4% holdout тоже частично фантомный,
**перепроверить на filled-only.** ФИКС (предложение, не прод-движок): `label_outcomes.py` — (1) проверять, дошла
ли цена до `entry` (иначе outcome=`NO_FILL`, не TP); (2) форсить SL при пересечении уровня. Это лейблер/журнал, не торговый код.

## ⚠️ ЧЕСТНАЯ ПЕРЕОЦЕНКА (fill-verified) — V3-ОПТИМИЗМ СНЯТ
Перегнал re-sim + sweep с **фил-верификацией** (вход на баре реального достижения уровня `entry`, hold от филла):
- **main_ws (n=59 филлов): V1 −0.57% / V3 −0.22% / oracle +1.87%.** Sweep: train НЕГАТИВЕН по ВСЕЙ сетке
  (−0.30…−0.35), holdout — шум (±0.2). **Плато исчезло — прежний «+0.4% / зелёная сетка» был фантомом нефилл-сделок.**
- **bb_fade (n=9): всё в минусе.**
- **На РЕАЛЬНЫХ филлах ни текущий выход, ни ATR-стоп+трейл НЕ плюсуют.** Ход после филла ЕСТЬ (oracle +1.87%),
  но adverse приходит ПЕРВЫМ (откатный лимит-вход филлит в слабость → стоп тагается → потом разворот). Простой
  стоп/трейл это не ловит — проблема глубже выхода, в **механике входа** (адверс-селекшн лимитки).

**ИТОГ (честно):** нарратив «main_ws тонко-плюсовой, чинится выходом» был построен на **баге лейблера** (фантомные
филлы). На честных данных — **доказанного эджа у живых каналов НЕТ.** Приоритет №1: **починить лейблер** (fill+stop) —
без него ВСЕ метрики (журнал/снапшот WR 75-80%) завышены. Потом честная переоценка каналов. Денег нигде нет (paper).
