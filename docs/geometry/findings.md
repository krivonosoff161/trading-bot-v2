# Geometry / Entry-Quality аудит — находки (24.05.2026)

**Статус:** research, read-only. Скрипт: `scripts/analysis/research/geometry_model.py`
(`python scripts/analysis/research/geometry_model.py` — пересобрать). Данные: тик-тейп `E:\trading-data\ticks`.

## Метод
Для каждой закрытой сделки реконструируем **post-entry** путь цены из тиков и меряем:
`post_mfe` (макс ход в нашу сторону ПОСЛЕ входа), `post_mae` (макс против), `net`.

**Важно:** записанный движком MFE был **завышен** — он считает по свечным high/low и
захватывает ход импульсной свечи ДО входа. Чистая метрика — наш post-entry тик-путь
(валидировано: окно входа выровнено gap +0s, опора = entry_price).

## Вывод (меняет приоритеты)
«WR ок, денег нет» — **не одна болезнь:**
- **impulse** — вход (заходили на выдохе спайка, lag ~2%). Мёртв, закрыт верно.
- **main_ws** — входы ХОРОШИЕ (MFE +1.34 > |MAE| 1.07, WR 56%, только 17% вход-в-топ). Чёткая
  диагональ «MFE→net». Убивают **несколько хвостов net −22/−24/−27%** (стоп не отработал / TIME до
  обвала) + мелкий тейк. ⚠️ хвосты проверить (реальные без-стопа ИЛИ артефакт неликвид-тейпа на TIME).
- **bb_fade** — входы ЛУЧШИЕ (MFE +2.47, до +14%; вход-в-топ 6%), но капчур проваливается
  (WR 38%, net −0.30): выбивает стопом до того как пойдёт движение.

**Живые каналы уже ловят ход — деньги теряются на ВЫХОДЕ/риске. Это fixable и это upside.**
Приоритет 0 = геометрия выхода/риска на main_ws + bb, а не новые движки.
