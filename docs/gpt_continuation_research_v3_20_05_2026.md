## Задача 1 — Разбивка long / short (проверка на фарт)

Пересчитать ВСЕ результаты V2 (по парам, паттернам, входам, выходам, буферам) **отдельно для
long и отдельно для short**. Для каждой комбинации:
`n_long, net_long, win_long` и `n_short, net_short, win_short`.

**Ключевой вывод, который нужен:** выделить параметры, положительные на ОБЕИХ сторонах при
`n >= 20` на каждой стороне. Это и есть проверка «реально или фарт».

Если плюс только на одной стороне — **явно сказать**: «edge односторонний → вероятно монета
сходила в одну сторону за окно данных, не закономерность».

## Задача 2 — Формальная математическая модель (НЕ подгонка)

Записать стратегию как **явную модель**, а не таблицу перебора:

1. **Entry rule** — точное условие входа (формула на признаках свечи/тиков):
   детект импульса (тело ≥ N× среднего за 3-4 свечи) + intra-триггер (X% за ≤ Y сек) + направление.
2. **Stop rule** — формула уровня стопа: экстремум импульсной свечи ± buffer.
3. **Exit rule** — формула выхода: слом структуры (закрытие за swing-уровнем последних k баров).
4. **Expected value (главное):** разложить ожидаемый результат на сделку, ОТДЕЛЬНО long/short:
   ```
   E[net] = p_win * avg_win - p_loss * avg_loss - fee
   ```
   + показать **mean vs median** (fat-tail shape) и разброс (std / IQR).
   Цель — понять: модель зарабатывает на стабильном перевесе или только на редких хвостах.

**Критично:** параметры модели фиксируются по ЛОГИКЕ (правила трейдера), их НЕЛЬЗЯ подбирать
так, чтобы максимизировать результат на этих 3 днях BSB — это overfit. Модель должна быть
осмысленной как правило, а прогон — её проверкой, не подгонкой.

## Задача 3 — Прогнать модель + устойчивость во времени

- Применить формальную модель на полной выборке, по сторонам, по парам.
- **Out-of-sample по времени:** разбить данные пары на 2 половины (ранние дни / поздние дни),
  проверить — держится ли результат на ОБЕИХ половинах. Если только на одной → неустойчиво.

## Задача 4 — Базовая модель (главный deliverable)

Выбрать ОДИН **base-model** — самый устойчивый набор: положительный на обеих сторонах, с нормальным
sample, держится на обеих половинах времени. Полностью специфицировать (все правила + параметры).

Если такого набора **нет** — сказать честно: «устойчивой базы нет; лучшее — X, но односторонне /
на одной паре / только на хвостах». Отрицательная база — тоже валидный результат, не натягивать.
