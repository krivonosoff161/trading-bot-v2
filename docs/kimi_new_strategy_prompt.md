## КОНТЕКСТ НАШЕЙ СИСТЕМЫ

**Стек:**
- Python + asyncio
- OKX Futures API (demo + real), цель — мультибиржа (Bybit, Binance)
- Telegram: клиент присылает запрос → система анализирует → отдаёт разбор + сигнал
- LLM: Gemma 3 27B-IT через Yandex AI Studio (vision, structured output)
- Индикаторы уже есть: EMA20/50, ADX, ATR, Bollinger Bands, Chandelier Exit, RSI(14), SuperTrend, Swing High/Low, Volume ratio

**Что провалилось (Strategy E — 0 сделок за 4 недели):**
- 5 условий одновременно: 1H bull + 15m near EMA + 15m structure + 15m weak pullback volume + 5m breakout + 5m vol
- Слишком жёсткий фильтр → сигнал почти никогда не срабатывал
- Когда срабатывал — SL выбивало раньше TP

**Результаты вчера (17.03.2026) — 5 позиций по анализу системы:**
- ETH LONG: TP1 достигнут в +14:30, но закрыт вручную по +8 вместо +200
- BTC LONG: SL сразу при открытии
- DOGE LONG: TP1 достигнут через 5ч, но позиция переждана до SL
- XRP SHORT: неверное направление, SL
- SOL LONG: SL за 8 минут до TP1 (wick вниз → потом пробой вверх)
- Итог: -282 USDT. При авто-TP на ETH+DOGE было бы +150 USDT

**Ключевой вывод:**
Сигналы направления частично правильные (ETH, DOGE, SOL пошли в нужную сторону),
но: SL слишком близко, нет авто-выхода по TP, нет trailing stop,
оператор закрывает вручную не вовремя.

**Архитектура (что строим):**
```
OKX/Bybit API → Python скрипт (индикаторы, свечи)
→ LLM (Gemma/Yandex) — анализ + решение
→ Telegram (клиент получает разбор)
→ авто-выставление лимитных ордеров + авто-TP/SL
```

**Ограничения:**
- Россия: Yandex AI Studio доступен, OpenAI/Anthropic — ограничены
- Нет WebSocket пока (только REST polling)
- Оператор не всегда у компьютера → нужна полная автоматизация TP/SL
