## 2. Корневая причина: фильтры прода vs бэктеста

### Что есть в бэктесте (`bt_bb_volume_5m.py` строки 322–367):

```python
not_thrust    = (h5[i] - l5[i]) < 1.5 * cur_atr      # фильтр импульсных баров
slope_fading  = slope_now < slope_prev                  # импульс должен гаснуть
```

### Что отсутствует в проде (`analyze_chart.py` строки 1641–1686):

- `not_thrust` — **нет**
- `slope_fading` — **нет**

Прод использует `_ranging5 = _adx_1h < 20` (строже чем бэктест `adx_max=22`), но это не компенсирует отсутствие thrust/slope фильтров.

### Количественное подтверждение (63-дневный кэш, BTC+ETH+DOGE):

## 4. Рекомендация: исправление прода

**Файл:** `scripts/analyze_chart.py`, строки 1641–1686 (BB FADE блок)

Добавить два условия перед генерацией сигнала:

```python
# 1. Отклонять импульсные бары (thrust)
bar_range_5m = _h5[-1] - _l5[-1]
cur_atr_5m   = calc_atr(_h5, _l5, _c5, period=14)[-1]
not_thrust   = bar_range_5m < 1.5 * cur_atr_5m

# 2. Импульс должен гаснуть (slope fading)
slope_vals   = calc_slope(_c5, period=5)
slope_fading = slope_vals[-1] < slope_vals[-2] if len(slope_vals) >= 2 else False

if not_thrust and slope_fading:
    # генерировать BB FADE сигнал
```

**Приоритет:** высокий. Без этих фильтров BB FADE в проде работает в 2× хуже бэктеста.

### Вывод по DRIFT:

1. **TIME_EXIT — главный убийца.** 34 из 90 DRIFT позиций (38%) не достигают ни TP ни SL за 150 минут. В TRENDING только 12%.
2. **XRP в DRIFT особенно плох:** 40% WR, 12/20 позиций — TIME_EXIT. Возможно, XRP в DRIFT просто не двигается к TP достаточно быстро.
3. **avg_R DRIFT = +0.042R** — практически нулевое математическое ожидание. Позиция занята, а профит минимален.

### Гипотезы для BACKLOG:

- **DRIFT hold time:** уменьшить max_hold для DRIFT с 150m до 90m — быстрее освобождать позицию
- **XRP DRIFT veto:** отключить DRIFT сигналы по XRP или увеличить TP порог
- **DRIFT TP**: использовать более агрессивный TP1 в DRIFT (0.6R вместо 0.4R) чтобы чаще закрываться до TIME_EXIT
