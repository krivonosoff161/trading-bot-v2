## 4 проблемы (диагностировано)

1. **Chasing the pump** — SL=11 мин говорит: входим в хвост, цена сразу разворачивается
2. **Кулдаун 120с** — LAYER 19 раз, WAL 3 сигнала за 5 мин (один и тот же памп)
3. **Pool thrashing** — пары вылетают через 5-10 мин, пул падает main=3 вместо 4
4. **Плохие пары** — PROS/OPG/RLS дали 0% WR, нужен сессионный бан

## Задача для GPT

### 1. Code review `_evaluate_entry` (главное)

Прочитай метод `_evaluate_entry` в `ws_pump_orchestrator.py`.

**Вопрос:** что конкретно менять чтобы:
- Не входить в хвост пампа (SL бьётся за 11 мин)
- Избежать re-entry на том же движении

**Идея для обсуждения:** входить не на spike-свече, а ждать откат (следующая 1m свеча ниже закрытия spike). Это retest-entry. Оцени риски и реализацию.

### 2. Code fix `_refresh_pool` — min dwell time

Прочитай `_refresh_pool`. Пара добавляется в pool → через 5 мин screener убирает её из universe → оркестратор сразу выбрасывает.

**Нужно:** если пара добавлена в pool, держать её минимум 30 мин (даже если screener убрал), при условии нет открытой позиции и нет бана.

Предложи конкретный diff, минимальные изменения.

### 3. Config recommendations

На основе данных предложи значения для `config.yaml`:
- `alert_cooldown_sec` (текущий: 120)
- `vol_mult` (текущий: 1.5)
- `price_pct` (текущий: 1.2)

### 4. Per-pair session ban

Сейчас: после 2 SL в main → counter → 2 SL в counter → ban 24h.
Проблема: PROS дал 3 SL за 3 минуты, счётчик SL ≥ 3 → cooldown 30 мин. Этого мало.

Предложи: если пара дала N SL без единого TP → сессионный бан (до конца дня UTC).
