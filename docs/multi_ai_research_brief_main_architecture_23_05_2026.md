## 2. ДИАГНОЗ МАЙН-ДВИЖКА (что нашли, дословно из кода и замеров)

### 2.1 Как сейчас считаются TP/SL (прод-код)
- **FAST стиль:** SL = `max(sl_k·1.2·ATR_15m, 0.4%)`, sl_k≈1.3–1.4 → ~**1.6–1.7·ATR_15m**.
  - TP1 = **0.5R если режим DRIFT**, иначе 0.8R.  TP2 = 1.5R.  (R = дистанция до SL)
- **SWING стиль:** SL = `sl_k(1.8)·1.2·ATR_15m` → ~**2.16·ATR_15m**.
  - TP1 = `min(1.0R, 0.5·ATR_1h)`.  TP2 = `min(2.5R, 1.2·ATR_1h)`.
- Холд: FAST 90–240 мин, SWING 300 мин.

### 2.2 Найденные болезни (наша интерпретация — проверь её)
1. **TP оторван от размера движения.** FAST = фикс R-кратное; SWING = кэп долей `ATR_1h`. Ни то ни
   другое не масштабируется от реально доступного хода.
2. **DRIFT FAST: TP1 = 0.5R** — рискуем 1, берём 0.5. Геометрия отрицательная; высокий WR — иллюзия.
3. **SWING TP закэплен `1.2·ATR_1h`** — превращает таргет 2.5R в ~1.05R, не даёт ехать по тренду.
4. **SL всегда от ATR_15m** — даже для SWING (держим до 5ч) → выбивает на внутридневных откатах.
5. **Память пампа смешана с интер-деем** — тесный скальп-TP прикручен к свинговой сделке.

## 4. ПРЕДЛАГАЕМАЯ АРХИТЕКТУРА (то, что нужно отревьюить)

Разделить ответственность: классификатор наверху, **3 пер-режимных анализатора со СВОИМИ
изолированными параметрами**, торговый оркестратор-исполнитель снизу.

```
РЫНОК(WS) → ОРКЕСТРАТОР-АНАЛИЗАТОР (классифицирует ХАРАКТЕР пары, скорость решается ЗДЕСЬ, роутит)
            → [Анализатор TRENDING(импульс,быстрый) | Анализатор DRIFT(медленный) | Анализатор RANGING(фейд)]
              у каждого СВОИ параметры входа/стопа/выхода
            → каждый кладёт САМОДОСТАТОЧНЫЙ сигнал:
              {пара, сторона, вход, стоп, правило_выхода(ride/scaled/fade), max_hold, сопровождение(BE@,trail@)}
            → ОРКЕСТРАТОР УПРАВЛЕНИЯ ТОРГОВЛЕЙ (тупой исполнитель: открыл/сопроводил/закрыл по инструкции;
              риск/нотионал/лимиты; уведомления/журнал/запись данных)
```

### Принципиальные решения
- **FAST/SWING как отдельная ось УБРАНА.** Скорость = личность анализатора (импульс=быстрый,
  тренд-ползание=медленный), решается при классификации, а не отдельным тегом. Это убирает матрицу
  3 режима × 2 стиля = 6 коллизирующих ячеек.
- **Каждый анализатор = один характер, один неймспейс параметров.**
- **Оркестратор торговли не имеет своей SL/TP/trail-политики** — исполняет инструкции из сигнала.

### 3 инварианта против коллизий
1. **Фичи/индикаторы считаются ОДИН раз наверху** → единый снапшот пары → анализаторы только читают.
2. **Один источник правды на каждое решение:** характер — классификатор; вход/выход — анализатор;
   риск/сопровождение — оркестратор. Никто не лезет в чужое.
3. **Одна пара → один анализатор** (режимы эксклюзивны); открытая позиция **залочена** за своим
   анализатором до закрытия (переклассификация влияет только на новые входы).

### 5 уже найденных точек коллизий (нужно найти больше)
1. Индикаторы считаются дважды (классификатор + анализаторы) → расхождение.
2. Стоп/TP в двух местах (анализатор задаёт + оркестратор крутит свой breakeven) → два источника правды.
3. Переклассификация на лету + неэксклюзивные режимы → две владелицы пары / дребезг у границы.
4. Общие ключи конфига → «изоляция» фиктивна, крутишь один — едут все.
5. Риск/нотионал/сессия в двух местах → двойная фильтрация / конфликт блокировок.
