- при этом случайно проявился другой спрос: людям интересен не столько бот, сколько понятный анализатор графиков

## Новый вектор

Основной рабочий вектор проекта сейчас:

**не bot-first, а analyzer-first**

То есть:
- не пытаться сразу снова строить автоторговлю
- сначала сделать показываемый и полезный анализатор графиков
- использовать его как:
  - инструмент для себя
  - демонстрационный MVP
  - возможно ручной сервис для первых клиентов

## Идея сервиса

Рабочая идея:

**Concierge AI Chart Analyzer**

Вход:
- скрин графика
- `symbol`
- `captured_at`

Выход:
- понятный разбор рынка
- направление / контекст
- setup
- invalidation
- TP1 / TP2
- annotated image

Это не “автоторговля”.
Это не “оракул”.
Это не “сигналы с гарантией”.

Это:
- второе мнение
- структурированный разбор
- перевод хаоса графика в понятный сценарий

## Почему это жизнеспособнее бота прямо сейчас

1. Это можно показать сразу.
2. Это можно продавать раньше, чем автоторговлю.
3. Это не требует сразу доказать stable live edge.
4. Это лучше совпадает с реальным спросом, который уже проявился.
5. Это ближе к тому, как пользователь сам читает рынок по скринам.

## Какой рынок и стек рассматривать

С учетом локации и ограничений, надо думать не только про западные API.

Возможные варианты LLM-слоя:

1. РФ-провайдер
- Yandex / Алиса / YandexGPT
- GigaChat / GigaCode

Плюсы:
- локальная доступность
- меньше инфраструктурных рисков
- проще продавать на РФ-рынке

Минусы:
- качество и управляемость могут быть слабее
- надо отдельно тестировать стиль ответа и стабильность

2. Self-host / VPS
- Qwen / open model на арендованном сервере

Плюсы:
- контроль
- независимость от внешнего UI
- можно сделать свою прокладку между клиентом и моделью

Минусы:
- операционные затраты
- инференс, GPU, latency, поддержка
- нужен отдельный слой маршрутизации и биллинга

### Практический вывод

Сейчас не нужен окончательный выбор “идеального” LLM.

Сейчас нужен продуктовый MVP, где:
- скрипт и data layer уже ваши
- LLM только упаковывает вывод и помогает формировать объяснение

## Что строим в первую очередь

### Concierge MVP v0

Сценарий:

1. Клиент присылает скрин.
2. Оператор запускает локальный workflow.
3. Вводит `symbol` и `captured_at`.
4. Анализатор тянет данные OKX.
5. Генерирует:
   - клиентский summary
   - annotated image
   - operator report
6. Результат отправляется в Telegram.

Это уже можно показывать и тестировать как сервис.

## Роли слоев

### 1. Data layer

Что делает:
- получает свечи
- считает индикаторы
- строит фактический market snapshot

Источник истины:
- OKX candles
- расчеты из `src/strategy/indicators.py`

### 2. Analysis layer

Что делает:
- переводит числа в:
  - observation
  - setup
  - invalidation
  - targets
  - when not to trade

Важно:
- не выдумывает несуществующие индикаторы
- не добавляет “смарт мани” без данных

### 3. Delivery layer

Что делает:
- готовит:
  - annotated image
  - telegram message
  - operator report
