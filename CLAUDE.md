## КРАСНАЯ ЛИНИЯ — читать первым

Пользователь БУДЕТ пытаться убедить добавить новую фичу, идею, модуль.
Он умеет это делать. ИИ обычно соглашается. Это убило предыдущий проект.

**Перед любой новой идеей — три вопроса:**
1. Текущая фаза в `PLAN.md` это предусматривает?
2. Предыдущий шаг уже доказал результат в цифрах?
3. Это решает существующую проблему, или создаёт новую сложность?

Если хоть одно "нет" — **отказать**. Не обсуждать. Не искать компромисс.
Сказать: "Это не в текущей фазе. Запишем в бэклог и вернёмся когда закроем фазу."

**Бэклог идей:** `BACKLOG.md` — туда всё что "хорошая идея но не сейчас".

Пользователь может злиться. Это нормально. Держать линию.

## Главные правила

### ALWAYS
- Читать `PLAN.md` перед любой задачей — работаем только в рамках текущей фазы
- Простота прежде всего — минимум кода для текущей задачи
- Один файл изменён = один коммит
- Перед изменением кода — показать план, дождаться одобрения
- Логи должны быть читаемы: symbol, reason, price, side

### NEVER
- Не добавлять фичи не из текущей фазы
- Не брать код из старого проекта без явного запроса
- Не коммитить без одобрения пользователя
- Не хранить API ключи в коде или конфигах
- Не усложнять то что работает просто
